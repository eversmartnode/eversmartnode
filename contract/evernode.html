Code Studio · HotPocket consensus state

CODE STORAGE: CONTRACT STATE — SUBJECT TO CONSENSUS
Frontend files such as index.html and evernode.html live directly in the contract state root; contract drafts under .contract-version-uploads/, and finalized application versions under contract-versions/ all live beneath the contract working/state directory. Every validator must converge on the same bytes. This is intentionally different from seed-local ../custom.json.
What is index.js vs sidedish.js? HotPocket starts index.js because hp.cfg → contract.bin_args points to it. In EverAdmin, index.js is a tiny protected bootloader/recovery layer. It chooses and starts the active sidedish.js. sidedish.js is the actual EverAdmin smart-contract logic you normally edit and update. If a new app version is broken, the bootloader can fall back to the built-in app instead of leaving the updater itself broken.
Stable loader protection: normally edit sidedish.js, not index.js. index.js can be viewed but is deliberately not overwritten from the panel because it is the recovery path.
Upload chunk target: 2 MiB raw file data per HotPocket input. The current hex transport makes that about 4 MiB plus BSON metadata on the wire.
